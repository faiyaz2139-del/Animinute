## Steering items (user said Fix)
- Edit Business Assignment - Assign Roles: Accountant and Administrator removed from the picker; Manager and Employee remain. UI only: a person who already holds a hidden role keeps it on save (no DB role rows deleted). The same control (EmployeeAssignment.aspx) is used for Add Business Assignment, so it applies there too. Add Employee (EmployeeEditor.aspx, different control) was not changed.
- Subscriber (Business Administrator) Dashboard: new App_Code/AnyminuteSubscriberDashboard.cs + css/AnyminuteSubscriberDashboard.css. Header + Business filter (All Businesses), 6 KPI cards, Quick Actions, Needs Your Attention, Weekly Hours Overview (week selector, Scheduled/Submitted/Approved totals, Mon-Sun Scheduled vs Submitted chart), Business Overview table with row menu, Recent Activity with View All. Real data only; zeros/empty states otherwise. Reference screenshot was not available on the box - built from the written description.
- Nav "View Business" under Businesses (subscriber) -> Businesses list.
- Businesses list: "Edit Business" under the business name renamed "Business Profile" -> new read-only BusinessProfile.aspx; its "Edit" button opens the existing Edit Business screen (owners only).
- Nav "View Employees" under Employees and "View Projects" under Projects (subscriber) -> existing lists. Work Schedule group labelled "Work Schedules" for the subscriber.
- Back button: Scripts/AnyminuteBackNav.js (Modern.master + Main.master) adds "<- Back" top-left above the page header on every screen except the Dashboard home; goes to the previous page on the site, else the screen's parent list, else Dashboard. Screens that already show their own Back link keep it.
- Left nav always visible: Scripts/AnyminuteNavDrawer.js + css/AnyminuteNavDrawer.css. Desktop (>=992px): permanent sidebar beside the content, no hamburger/collapse; sub-menus still expand. Narrow screens: open by default on each page, can be closed with the menu button. Accountant and Support Admin keep their existing pinned modes.
- Add/Edit Employee (EmployeeEditor.aspx): placeholders now use masks instead of sample values - Contact Phone and Mobile "(###) ###-####"; Address Lookup Postal/ZIP "X#X #X#" (switches to "#####" when the lookup country is United States); manual address Postal/ZIP "X#X #X#" (switches to "#####" when Country = United States); SIN "### ### ###" kept. Email label no longer shows "(To grant online access)". Scripts/AnyminuteAddressLookup.js (shared with EmployeeProfile.aspx, cache-bust bumped on both) sets the country-dependent postal placeholders. Left as-is: descriptive placeholders that are not sample values ("Enter first name", "Enter address line 2 (e.g. Unit, Floor)", "e.g. Increase in hourly pay rate." in the rate-change reason box), and the help line under the lookup "Enter a valid Canadian postal code (e.g. M1B 2W1) or US ZIP code (e.g. 33185)." (help text, not a placeholder). Legacy pages (Add_EmployeeV2, Edit_EmployeeV2, etc.) not changed.
- Add Employee does not grant login access: EmployeeEditor (add mode) always creates the employee with login access off and sends no invitation. The login row the legacy create needs is still created but is marked disabled (AnyminuteLoginSecurity), and no password or invitation is sent. If that email already has a login (same person in another business) its access is left exactly as it is. Access is granted later from Employee Details > Login & Access: the button reads "Send Invitation" while access is off - it turns login access on (audited "LoginEnabled - Access granted (invitation)") and sends the existing invitation email; for enabled logins it stays "Resend Invitation". The Edit Employee Login & Access "Resend Invitation Email" uses the same grant-and-send. Invitation tile shows "Not sent" until an invitation is actually sent (the "sent" date now comes only from SendInvitation, not from employee creation). No data changes or migrations; existing employees are untouched. If the AnyminuteLoginSecurity table is not installed, the new login cannot be flagged disabled, but nobody receives its credentials until an invitation is sent.
- Pop-ups converted to full pages (Edit Employee card style, "<- Back" top-left, all fields and actions kept):
  1. Edit Business Assignment / Add Business Assignment (EmployeeAssignment.aspx, opened from Employee Details): the editor replaces the list on the page; Back/Cancel returns to Employee Details when opened from there, otherwise to the assignment list; Save unchanged.
  2. Add Employee > Add Business Assignment (EmployeeEditor.aspx): full page; the employee form is hidden (still posted, so nothing typed is lost); Back/Cancel/Add return to the form.
  3. Weekly Time Card > Manage Breaks (WeekTimeCard.aspx): full page; Back and Done return to the time card (typed time-card values are kept, as before they are not saved until Save).
  4. Add/Edit Business > Enter Address Manually (Add_Business.aspx + Scripts/AnyminuteBusinessEditor.js): shown as a full page with Back; Cancel/Back/Escape restore the business form.
  Left as small confirms: Projects > Delete Project panel (delete confirmation), browser confirm() prompts (remove assignment, cancel invitation, deactivate, copy week). Left untouched: legacy pages not in the subscriber menu that use the old AjaxControlToolkit pop-ups (e.g. Home_Page, Time_Sheet_Entry*, Ticket_List, PostalCode*, SearchAddress, Permission_Role_Master, CreaetUserType, AddEditRole_Add_Employee, legacy EmployeeProfile.aspx address lookup). Employee Details > Documents upload is an inline form (not a pop-up).
- "Edit Info" / "Edit Basic Info" labels: searched every page, code file and script - the only one (Employee Details header) was already renamed to "Edit" in v85; no other "Edit ... Info" label exists, so no further change.
- Deploy fix: the first v86 deploy stopped at the server compile (nothing changed live) - BusinessProfile.aspx had a Literal with ID "Profile", which clashes with ASP.NET's generated Profile property. Renamed to ProfileLit. A full server-style compile re-check of every page/master/control changed in v85-v86 found nothing else (see COMPILE_v86.txt).
